# Submitting a support ticket or bug report

## Before you start

Support works on the login page and while signed in. You can submit directly without Ollama or an AI conversation. Sending requires internet. Support emails go to the configured fixed support recipient for follow-up.

## Steps

1. Open Support / Report a bug.
2. Describe the subject, priority, screen/action, steps that triggered it, expected behavior, actual behavior and exact error. Include the app version and whether the operation is uncertain/saved if known.
3. When signed out, enter a reply email carefully; it is a user-supplied, unverified contact. Signed-in reports use the staff context shown.
4. Add appropriate screenshots/files and review diagnostics. Keep passwords, tokens, full payment details and private customer data out of the description.
5. Review the report details and attached files. CERMS Assistant is a separate help window; closing or finishing its chat does not submit a bug report, and reporting a bug does not start or end an assistant chat.
6. Deliberately Send. Wait for confirmation; keep the same request for a retry after an uncertain result.

## GitHub availability

The public CERMS issue integration is prepared but requires the owner's runtime credential setup/activation. When enabled, report description/app details can become public and the support email includes the issue link. Contact details, diagnostics and private attachment links stay in email. Do not promise an issue exists just because a ticket was sent. Existing email-only support remains useful until integration is activated.
