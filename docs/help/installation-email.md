# Installation and update confirmation emails

## What triggers the email

After an installed tracked version successfully signs in, CERMS reports that installation/version to the designated administrator. It identifies the first user to sign in, installed version, computer name, operating system/architecture and a persistent installation identifier. Each device installation is tracked separately.

## Expected process

1. Install/update CERMS, then reopen it.
2. Sign in successfully using your own staff account.
3. Continue working; email availability does not block the workspace.
4. Check Settings for the actual running version if the owner asks which update you installed.

## Limits and troubleshooting

Repeated ordinary logins on the same installation/version do not produce another email. A failed login, merely downloaded update or development preview does not count as a completed installed update. The first tracked version may report a baseline with no known previous version; it does not invent older installation history.

The installation identifier normally survives updates, but this is not a hardware-serial inventory system or proof of the exact person who clicked Install. Device names are reported by the client. Do not reinstall repeatedly or change profile version fields to provoke a notification. If the owner receives none, report installed version, successful-login time and connection status; do not send a real test login/email from support or claim delivery is guaranteed after an ambiguous mail result.
