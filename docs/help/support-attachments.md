# Attaching screenshots and downloading support files

## Submitter steps

1. In Support / Report a bug, capture the offered CERMS screenshot or choose local attachment files.
2. Review screenshots for customer/payment information before adding them. Keep public report text free of private data even when attachment links are private.
3. Stay within ten files and 8 MB combined, across the report attachments.
4. Remove unintended attachments before sending. The report's deliberate Send action uploads/submits them; selecting a file alone is not confirmation of delivery.

## Recipient steps

1. In the formatted support email, identify the intended filename and attachment link.
2. Follow the download link to obtain the originally uploaded image/file with a useful filename, extension and type.
3. If the browser previews a supported format, use its download action to save it. A signed private link may expire; ask support to review/regenerate access through the authorized process rather than making storage public.

## If something is wrong

Report the filename/type, whether preview or download failed and the browser/app error. Do not post private signed links publicly. New uploads preserve originals; formatting improvements do not rewrite older stored attachments. This workflow is different from product images, which store optimized copies, and member-profile files, which have their own per-file limit and access controls. Never rename arbitrary downloaded content to an image extension to disguise its actual type.
