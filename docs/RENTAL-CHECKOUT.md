# Rental checkout

Overview and Admissions & rentals expose **Check out rental** in the shared View dialog for the fixed owner and saved-business staff with `processSales`. Staff must separately confirm **The rental is completed** and **All required items have been returned** before **Confirm rental checkout** becomes available. Canceling clears both confirmations and writes nothing. Unsaved edits must be saved or discarded before beginning checkout.

`checkOutRental` operates only on named `cerms`. The callable rechecks saved business, current sales permission, active rental, revision and expiry inside a transaction. The confirmation captures revision and expiry when it opens; a concurrent edit or paid renewal requires reopening and reviewing the rental. Both confirmations must be literal `true` at the request guard and server. Direct desktop activity/member writes remain blocked.

Completion preserves the rental, assignment, time history, product/order metadata and notes. It marks the selected activity inactive/outside/off-waitlist and records authenticated closer UID, server time and both confirmations. A transaction queries the member's visits using the existing single-field `memberID` index, considers active visits only within the selected business and updates the admission claim. Other active visits keep the member admitted; the final checkout removes the claim and sets only the member's `checkedIn` field to false. Older visits without claims are supported. Missing/foreign members and inconsistent claims fail for review rather than modifying another admission. Paid sales, inventory, register totals, receipts, Auth and Storage are untouched.

A retry of the same confirmed revision/expiry by the same authorized staff member returns success without additional writes. Completed rentals cannot be edited or renewed. Closed activity remains as history and automatically leaves both active subscriptions and rental alerts.

Deploy only `functions:cerms-staff:checkOutRental` via `firebase.checkout.json`. Standing Firebase deployment authorization applies. `scripts/rental-checkout-deployment.mjs before|after` verifies the current theme rules release and compares all rule releases, both databases' settings/indexes, both buckets and every other function. No rules, indexes or existing functions need deployment. Evidence: `docs/RENTAL-CHECKOUT-DEPLOYMENT.json` after successful verification.
